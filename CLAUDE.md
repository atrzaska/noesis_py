# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Noesis-Py is a pure-Python (**Python 3**) reimplementation of Rich Whitehouse's *Noesis*
model/image/animation viewer. The goal is source-level compatibility: plugins written for the
original (closed-source, Windows/native) Noesis should load and run here **unchanged**. That
compatibility constraint drives most design decisions — the public API (`noesis`, `rapi`,
`inc_noesis`) must mirror the official one exactly, even where the implementation is incomplete.

Only basic model *viewing* works today; large parts of the API are stubs (see "Not implemented").

## Commands

```sh
direnv allow                    # loads .envrc: adds ./bin to PATH, ./pip to PYTHONPATH
setup                           # bin/setup: pip3 install -r requirements.txt -t pip, then applies PyOpenGL patch
noesis ~/Desktop/model.pmx      # bin/noesis: runs python3 lib/NoesisApplication.py "$@"
noesis a.pmx b.pmd              # multiple models load into one scene
DEBUG=true noesis model.pmx     # logs every not-yet-implemented API method that gets called
SCALE=2 noesis model.pmx        # 2x window size
cleanup                         # bin/cleanup: removes all *.pyc and .DS_Store
```

- Requires **cpython3 / pip3** (`python3`, `pip3` on PATH) and **direnv**. The codebase was migrated
  from Python 2 (commit `fd94e8c "Move to python3"`); do not reintroduce Python 2 syntax.
- Dependencies are vendored into `pip/` (see `requirements.txt`), added to `PYTHONPATH` via `.envrc`.
  `pip/`, `data/`, and `lib/noesis_plugins/` are gitignored — treat `pip/` as generated by `setup`.
- No test runner and no linter are configured. `lib/plugins/fmt_noetests.py` is a ported Noesis
  self-test plugin, not a CI suite.

### Finding unimplemented work
The README's recommended workflow uses `ag` (the_silver_searcher):
```sh
ag logNotImplementedMethod       # every stubbed API function
ag "\*args"                      # stubs whose real signature is still unknown
```

## Architecture

Runtime entry point is `lib/NoesisApplication.py`. There is no native binary — the modules a real
Noesis plugin expects (`noesis`, `rapi`, `inc_noesis`) are ordinary Python packages under `lib/`,
resolved because `lib/` is the working dir when `bin/noesis` runs.

### The three API surfaces (compatibility layer — mirror official Noesis, do not restructure)
- **`lib/noesis/`** — the `noesis` module. `__init__.py` defines all constants (`RPGEO_*`,
  `NOESISTEX_*`, `RPGEODATA_*`, …) and top-level functions. It self-registers as
  `this = sys.modules[__name__]` and keeps global `this.plugins` (registered `Handler`s) and
  `this.modules`. Key helpers: `register(name, ext)` → `Handler`; `allocType(...)` → `AllocType`
  (a `BytesIO`-backed bitstream used by `NoeBitStream`). `AllocType.py`, `Handler.py`, `NoeModule.py`
  are supporting classes.
- **`lib/rapi/`** — the `rapi` module. Runtime-context API; **only valid during plugin load/handler
  callbacks**. `Context.py` accumulates vertex/normal/uv/etc. buffers and `commit(...)` turns them
  into a `NoeMesh`. Tracks `lastCheckedName` (the file being loaded) used for resolving relative
  texture paths.
- **`lib/inc_noesis.py`** — the `inc_noesis` module plugins do `from inc_noesis import *`. Pure-Python
  wrappers/classes: `NoeBitStream`/`NoeUnpacker` (binary reading), `NoeVec3`/`NoeVec4`/`NoeMat43`
  math types, and the scene model types `NoeMesh`, `NoeModel`, `NoeModelMaterials`. **Do not modify
  gratuitously** — the file header warns it is integrated with the (would-be) native module and
  changing class shapes breaks plugin compatibility.

`lib/util/` holds non-API helpers, notably `logNotImplementedMethod(name, args)` which prints only
when `DEBUG=true` — every stub calls it so you can see what a given plugin actually needs.

### Load → render flow
1. `NoesisApplication.run()` discovers plugins via `glob("lib/plugins/fmt_*.py")`, imports each, and
   calls its `registerNoesisTypes()` — which calls `noesis.register(name, ext)` and attaches
   callbacks (`noeSetTypeHandler_LoadModel`, etc.) to the returned `Handler`.
2. For each CLI file, `loadFile` matches extension against registered `Handler.format`, sets
   `rapi.setLastCheckedName(file)`, and calls the plugin's `loadModel(data, mdlList)`. The plugin
   parses bytes and appends a `NoeModel` (with `.meshes` and `.modelMats`) to the list.
3. `lib/NoesisViewer.py` opens a pygame + PyOpenGL window and, per model, builds a
   `lib/NoesisLoader.py`. `NoesisLoader.render()` compiles the meshes into a GL display list
   (`glNewList`) — iterating `mesh.positions/normals/uvs/indices`, resolving materials/textures via
   `modelMats`, and applying per-loader `flip*`/`scale` transforms. The viewer then runs a fixed
   mouse-orbit loop (LMB rotate, RMB pan, wheel zoom, Esc/close to quit).

### Plugins (`lib/plugins/`)
Each `fmt_<game>_<ext>.py` is a self-contained format handler following the Noesis plugin ABI:
module-level `registerNoesisTypes()` + a `loadModel(data, mdlList)` that uses `NoeBitStream` to
parse and `rapi`/`inc_noesis` to build meshes. `tool_*.py` are ported tools, `data_*` / `inc_*` are
shared helpers. When adding format support, add a plugin here — **do not** special-case it in the
loader/viewer.

## Conventions & gotchas
- **Python 3.** Note that `noesis`/`rapi` rely heavily on `map()`/`filter()` — remember these now
  return lazy iterators, so several call sites wrap them in `list(...)` (e.g. `unpackBuffer` in
  `lib/rapi/__init__.py`) where the result is indexed or reused. Watch for iterator-exhaustion bugs
  when porting old plugin code. Intra-package imports are absolute (`import rapi.pvr`,
  `from rapi.Context import Context`), not implicit-relative.
- Compatibility trumps cleanliness: preserve exact function names, argument order, and class
  attributes in `noesis`/`rapi`/`inc_noesis` even when reimplementing. Prefer implementing a stub
  over changing its signature. Known signature gaps are noted in `TODO`.
- Performance is a known pain point: every buffer value is unpacked into Noesis Python objects, which
  makes loading slow (README "Problems"). Recent commit history reflects work to avoid unpacking
  buffers in `rapi`.
- Face-buffer break value `0xFFFF` (65535) starts a new primitive strip in the loader; other break
  encodings are not handled yet (`TODO`).
- The PyOpenGL patch in `patches/` fixes a compressed-texture call (`ArrayType` → `ArrayDatatype`)
  and is applied by `setup`; a fresh `pip/` needs it re-applied.

## Not implemented
Most of `noesis`/`rapi` are stubs that just call `logNotImplementedMethod`. Animations, skeletons/
bones, writing/exporting, and many texture formats are absent. Consult `TODO` and a `DEBUG=true`
run before assuming an API function does real work.
